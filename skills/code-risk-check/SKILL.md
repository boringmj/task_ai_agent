# 代码风险检查

给任意代码载体(代码片段、脚本、安装包、仓库)做一次**行为导向**的风险体检,产出三样东西:

- **行为清单**:读、写、删除、网络、执行、持久化、提权、隐私采集、凭据访问、加密破坏、反分析、供应链 —— 逐项给结论,每条带证据(`文件:行号`)。
- **安全等级**:L0 无风险 → L4 恶意程序,附 LX 无法判定。
- **类型标签**:主类型 + 修饰标签。

这个技能回答的是「**它跑起来会做什么**」,不是「它写得有多烂」。代码质量、性能、已知漏洞利用面属于 `repo-security-audit`,不由本技能负责。

## 四条铁律

1. **看行为,不看宣言。** README、注释、变量名、"本工具不会上传任何数据" 都只是**待验证的声明**。代码做了文档没写的事(或反之),本身就是一条高风险 finding,要单列。
2. **不确定不得当作无风险。** 强混淆、动态加载、运行时从远端取码这类无法静态判定时,等级填 `LX 无法判定`,并写清还差什么才能定。默认"没看出来就是安全"是本技能最严重的错误。
3. **不可信的代码只在沙箱虚拟机里运行。** 绝不在宿主或容器里执行待检样本。静态扫描(只读文本)可以在容器里跑;要真跑,走 VM(见 `references/dynamic.md`)。
4. **副作用和依赖必须写全。** "它做什么"里最要紧的是**副作用**:跑完会在磁盘上留下什么、写到哪里、退出时清不清理。纯计算代码(输入 → 输出,不落盘、不起进程、不出网、不改环境)就是**无副作用**,标 L0 并写明"无副作用"四个字;有副作用的一律写清**产生什么、落在哪条路径、是否残留**。同时列清**运行时依赖**:什么语言与最低版本、哪些第三方库、必须存在哪些系统命令、需要哪些环境变量或凭据、限哪个平台。这两样是报告的必备章节,不能省。

## 流程

### 1. 摸清范围与形态

先 `list_files` / `find_files` 看清给了什么:单文件、目录、仓库还是压缩包。记录语言、文件数、总行数、有无二进制或编译产物。

同时判断**是否已混淆**:变量名乱码、超长单行、大量 `\x` 转义、大块 base64、eval 套娃。混淆本身就是一条 finding,并直接抬等级 —— 正常工具没有理由隐藏自己的逻辑。

代码量很大时不必逐文件读;先靠扫描定位热区,只精读命中的文件。

### 2. 静态扫描

跑扫描脚本拿到候选点:

```bash
python3 /skills/code-risk-check/scripts/risk_scan.py <目标路径> --json findings-risk.json
```

它按「行为维度 × 语言」匹配危险 API 与敏感路径,输出每条命中的文件、行号、代码片段、所属维度,以及**潜在等级上界**。

**扫描结果是线索,不是结论。** 正则必然误报(字符串里出现 `curl `、注释里的示例、文档里的示例代码),所以每条命中都要读上下文复核,把"确实会执行"的和"只是提到"的分开。报告里只写核实过的。

### 3. 追踪数据流(这一步决定等级)

真正定级的不是"用了什么 API",而是「**数据从哪来、到哪去**」。对每条网络和文件命中,顺着变量往回追:

- **源**:读的是用户文档、程序自己的配置,还是凭据 / 密钥 / cookie / 浏览数据 / 聊天记录?
- **汇**:写本地、写日志,还是 POST 到公网?
- **路径**:把敏感变量一路跟到请求体。典型恶意形态就是「读浏览器 cookie → 拼进 POST body → 发往硬编码 IP」。

然后对照 `references/behaviors.md` 的 12 个维度逐条给结论(是 / 否 / 不适用 + 证据)。

### 4. 动态验证(可选,高风险与混淆样本必做)

静态看不懂、或要确认"它到底有没有真的往外发"时,在 VM 里跑一次并观察:

- 跑前跑后对关键路径做快照,比对文件系统改动;
- 用本地记录型服务 + hosts 劫持,把出站请求引到观察点,看它**想**发什么(而不是真发出去);
- 轮询连接表,记录它尝试连接的目标。

具体命令见 `references/dynamic.md`。**先把网络断掉或指向本地观察点,再执行样本。**

### 5. 定级与打标签

按 `references/levels.md` 先给每个维度定小级、取最高,再用四条修正规则(隐蔽性 / 数据敏感度 / 目的地可信度 / 文档一致性)调整。

**副作用清单为空才有资格判 L0。** 哪怕只是写了一个临时文件、建了一个缓存目录、改了一个环境变量,也是 L1;每一条都要落到"产生什么、写在哪条路径、退出后是否残留"。标签按下一节给。

### 6. 出报告

用 `references/report-template.md` 的结构写报告(用户指定文件名时从命,否则 `<目标名>-风险检查.md`),并保留扫描 JSON 作为证据。

**副作用清单**和**运行时依赖**是必备章节:前者给"产生什么 / 写到哪里 / 退出后是否残留",后者给"语言与版本 / 第三方库 / 必须存在的系统命令 / 环境变量与凭据 / 平台限制"。报告要能让没读过代码的人一眼看懂结论和依据。

## 安全等级

| 级别 | 名称 | 判据(满足即入该级,多条命中取最高) |
| --- | --- | --- |
| L0 | 无风险 | **副作用清单为空**:只读自身输入与配置,不写盘、不建缓存、不起进程、不出网、不改环境、不触碰用户数据,退出后系统里不留任何东西 |
| L1 | 环境修改 | 改变本机环境但限于本地、与功能相符:写删文件、建缓存、改配置、装依赖、起子进程、写日志。不触碰隐私,不出网 |
| L2 | 隐私读取 | 读取隐私或敏感数据(凭据、密钥、cookie、聊天与浏览记录、文档、剪贴板、屏幕、摄像头麦克风、位置、设备指纹),但未发现外传 |
| L3 | 数据外传 | 数据被发往外部:上传、回传、回连、与外部服务的双向通信;含「读到隐私 + 有出网」的组合 |
| L4 | 恶意程序 | 有恶意意图的证据:隐蔽窃取并外传、后门或远控、勒索加密、破坏数据、挖矿、横向移动、反沙箱反调试规避 |
| LX | 无法判定 | 混淆、加壳、运行时取码、加密载荷,静态定不了也不便动态验证。**不得按 L0 处理** |

四条修正规则(详见 `references/levels.md`):

- **隐蔽性**:刻意隐藏(混淆、无文件、延迟触发、随机域名、抹日志)→ 至少上调一级。
- **数据敏感度**:凭据密钥 > 个人隐私 > 内部业务数据 > 公开数据。
- **目的地可信度**:官方 API 或用户自配地址 > 未知第三方 > 硬编码 IP:端口 / 域名生成算法。
- **文档一致性**:代码做了文档没说的事(或相反)→ 上调,并单列一条 finding。

用户自述用途**不作为定级依据**,但要记进报告 —— 用来交叉验证"代码行为是否与宣称一致"。

## 类型标签

**主类型**取一个,拿不准就选 `unknown`:

`tool`(工具 / CLI)、`script`(脚本 / 胶水代码)、`service`(常驻进程 / 服务端 / API)、`business`(业务应用逻辑)、`framework`(框架)、`library`(库 / SDK)、`plugin`(插件 / 扩展)、`template`(模板 / 脚手架)、`config`(配置 / 数据)、`test`(测试 / 示例)、`ci`(构建 / 部署 / CI)、`unknown`

**修饰标签**可多个、允许自造,用小写连字符,自造的在报告里注明含义。常用:

`obfuscated`、`packed`、`installer`、`downloader`、`network`、`filesystem`、`crawler`、`bot`、`agent`、`crypto`、`privilege`、`persistence`、`kernel`、`ml`、`security`、`supply-chain`、`miner`、`infostealer`、`backdoor`、`ransomware`、`rat`

写法示例:`script + network + obfuscated`、`service + crawler + filesystem`、`tool + infostealer + persistence`。标签是判断,依据要能在报告里指出来 —— 别凭感觉打。

## 参考与脚本

- `references/levels.md` —— 等级详细判据、修正规则、副作用定义、常见组合的定级示例
- `references/behaviors.md` —— 12 个行为维度的检查要点、副作用与残留的排查项、运行时依赖清单、各语言危险 API 速查
- `references/report-template.md` —— 报告结构与 findings JSON 字段(含副作用清单、运行时依赖两节)

- `scripts/probe_http.py` —— 记录型 HTTP 服务,把出站请求引到观察点并留档
