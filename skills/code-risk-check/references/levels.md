# 安全等级:详细判据

等级是**对"它跑起来会做什么"的判断**,不是对代码质量的评价。逐维度定小级 → 取最高 → 按四条修正规则调整。

## 先分清:什么是副作用

副作用 = 除了「读入 → 算出 → 输出」之外,程序对外部世界做的任何改动。报告里逐条列清,每条回答三个问题:

- **产生什么**:文件?目录?缓存?日志?进程?连接?环境变量?注册表项?计划任务?
- **写到哪里**:给出具体路径(如 `~/.cache/mytool/state.json`、`/tmp/xxx`、`C:\Users\<用户>\AppData\Local\...`),或是相对于什么(当前工作目录、脚本所在目录、用户主目录)。路径由参数或配置决定时,写明**默认值**。
- **退出后是否残留**:进程结束后还在不在?异常退出会不会留下锁文件、临时文件、半成品?静态看不出来就标"需动态确认",用 `scripts/fs_snapshot.py` 跑一次前后比对。

常见副作用来源,别漏:

| 类别 | 例子 | 关注点 |
| --- | --- | --- |
| 数据文件 | 输出结果、导出的表 | 落在当前目录还是用户指定位置,会不会覆盖同名文件 |
| 配置与状态 | 配置文件、`.state`、缓存 | 常落在 `~/.config`、`~/.cache`、`%APPDATA%` |
| 临时文件 | `/tmp`、`tempfile` | 关键看**是否清理**、异常退出时是否残留 |
| 日志 | `.log`、日志目录 | 会持续增长,且常含敏感内容 |
| 锁 / PID 文件 | `.lock`、`.pid` | 崩溃后残留会让下次启动卡住 |
| 编译产物与缓存目录 | `__pycache__`、`.cache`、`node_modules` | 体积可能很大 |
| 系统状态 | 环境变量、`PATH`、hosts、注册表、计划任务、服务 | 影响面超出自身目录 |
| 进程 | 常驻服务、后台子进程、守护进程 | 主程序退出后可能仍在跑 |

**一条都没命中时,报告里明确写「副作用:无」** —— 这是 L0 的必要条件,不能靠"没看出来"糊过去。

## L0 无风险

- 判据:**副作用清单为空**。纯计算就属于这一类 —— 输入进来、算完、输出(打印或返回),不落盘、不建缓存、不起进程、不出网、不改环境、不碰用户数据、退出后不留残留。
- 典型:数值与文本计算、格式转换、对传入内容的静态分析、只读取自身配置、结果只打印或返回。
- 边界判定:
  - 读环境变量、命令行参数、自身目录下的配置 → 不算隐私,仍 L0。
  - 读取的路径可配置,而默认值指向用户数据 → 按默认行为定级。
  - "不写盘"是指不留下任何东西;**只要创建了文件(哪怕会自清理的临时文件),就按 L1 记**,并在副作用清单里写明路径。

## L1 环境修改

- 写入或删除文件、创建缓存与日志、修改自身配置、安装依赖、拉起子进程、改 `PATH`、改 shell rc。
- 只要改动限于"跑它所需的本地环境"、不触碰隐私、不出网,就是 L1。
- 凡是产生**退出后仍残留**的东西(缓存、日志、配置文件、锁文件、临时文件),至少 L1;残留位置在用户主目录或系统目录时,报告里写全路径。
- 边界判定:
  - 写系统目录(`/etc`、`System32`)、写开机自启、加计划任务 → 仍 L1,但必须带 `persistence` 标签,并在报告里单列。
  - 覆盖或删除用户已有的文件(`shutil.copy` 到已存在路径、`rm -rf` 目标可能是用户目录)→ L1 顶格,有数据丢失风险时上调并明示。
  - 修改 shell 启动文件(`~/.bashrc`、`~/.zshrc`、PowerShell profile)→ L1 + `persistence`。

## L2 隐私读取

只要**读取**了下列数据,不管读来干嘛、有没有用上,都入 L2:

- **凭据**:SSH 私钥、云凭据(`~/.aws/credentials`、`~/.kube/config`)、`.netrc`、`.git-credentials`、`.npmrc`、token、密码库、keychain。
- **个人内容**:聊天记录、邮件、文档、照片、浏览器历史与书签、下载目录。
- **浏览器数据**:`Login Data`、`Cookies`、`Web Data`、`Local State`、`leveldb`。
- **感知数据**:键盘输入、剪贴板、屏幕、摄像头、麦克风、位置。
- **设备指纹**:硬件 ID、MAC、SSID 列表、`/etc/machine-id`、主机名与内网信息。

边界判定:

- 杀毒、备份、同步、输入法这类工具的读取是核心功能,仍记 L2,报告里注明"与功能相符";一旦它们外传,直接落到 L3/L4。
- 读用户**主动指定**的那一个文件(如 `本工具 报告.docx`)视为符合预期的输入,可记为 L1 —— 但若顺手扫描同级目录或整个用户目录,回到 L2。
- 读到路径里含 `user` 不代表隐私;程序自己写的缓存/日志不是隐私数据。

## L3 数据外传

任何出站传输都要看一眼**内容**再定级:传的是遥测统计、版本检查,还是用户数据?

入 L3 的情形:

- L2 级别的数据被发出去(哪怕只发了主机名、用户名、内网 IP 也算)。
- 本机文件内容、目录列表、进程列表被上传。
- 与外部保持双向通信 —— 若对端能下发指令,直接按 L4 评估。
- 上传内容"夹带"了用户没指定的额外信息(设备指纹、账号、文件清单)。

边界判定:

- 程序自己的崩溃日志、版本号,且不含用户数据 → L1(但要注明是否默认开启、能否关闭)。
- 用户指定内容 + 用户自己填的目的地(如"把这段文本发到我配置的 webhook")→ L1。
- 默认开启、无法关闭的遥测且带设备标识 → L3。
- 硬编码 IP:端口、明文 HTTP、域名生成算法、无 TLS → L3 顶格,考虑 L4。

## L4 恶意程序

要求**隐蔽性 + 危害性**同时存在。典型形态:

| 形态 | 特征组合 |
| --- | --- |
| 信息窃取 infostealer | 读浏览器 cookie / 密码 / 钱包 + POST 到外部 + 无任何说明 |
| 后门 / 远控 RAT | 反向 shell、C2 心跳、远程下发命令并执行 |
| 下载器 downloader | 从 URL 拉二进制并执行、后续载荷由远端决定 |
| 勒索 ransomware | 遍历文件加密、写勒索说明、删卷影或备份 |
| 破坏 wiper | 批量删除或覆写数据、破坏引导 |
| 挖矿 miner | 连矿池、静默占满 CPU/GPU、隐藏进程 |
| 横向移动 | 扫内网、SSH/SMB 爆破、写其他主机 |
| 规避 evasion | 反 VM / 反调试 / 反沙箱、隐藏自身、抹日志 |

判定要点:

- 意图看**行为组合与一致性**,不看名字。`读 cookie` + `发往硬编码 IP` + `开机自启` + `零文档` 就是 L4,不需要抓到真正的窃取代码。
- 单看任何一个动作都可能"有正当解释",但组合起来不存在合理的正当用途时,按恶意定。
- 恶意代码自称"安全工具 / 渗透测试"不改变定级,只在报告里记录这一陈述。

## LX 无法判定

- 触发:强混淆、加壳、运行时从远端取码、加密载荷且无密钥、样本无法获取(只有二进制没有源码)。
- 处理:不得标 L0。报告写清原因、已知的少量线索、以及下一步需要什么(需要动态跑 / 需要密钥 / 需要样本本体)。
- 后续:去混淆可以配合 `code-deobfuscation` 技能;样本本体只放 VM 里。

## 修正规则(在维度最高级之上再调)

| 规则 | 方向 | 说明 |
| --- | --- | --- |
| 隐蔽性 | 上调 | 混淆、无文件执行、延迟触发、随机或生成式域名、抹除日志 —— 正常功能不需要这些 |
| 数据敏感度 | 影响定级 | 凭据密钥 > 个人隐私 > 内部业务数据 > 公开数据 |
| 目的地可信度 | 上调 | 未知第三方 < 硬编码 IP:端口 / 域名生成;官方 API 或用户自配地址 < 一切未知对端 |
| 文档一致性 | 上调 | 代码做的事文档没提(或相反);"只读取,不上传" 却出现 POST |
| 用户可知情 | 不上调 | 明确告知、可选开启的行为,记一句"用户知情"即可,不额外升级 |

## 常见组合 → 等级

| 行为组合 | 等级 | 标签示例 |
| --- | --- | --- |
| 纯计算,读参数,打印结果 | L0 | `script` |
| 生成报告文件到当前目录 | L1 | `tool + filesystem` |
| 装依赖、改 `~/.bashrc`、加 cron | L1 + persistence | `installer + persistence` |
| 扫描本机文件统计磁盘占用 | L1(读的是元数据) | `tool + filesystem` |
| 读浏览器 cookie,不发出去 | L2 | `tool + infostealer`(仅为行为标签) |
| 截屏存本地 | L2 | `tool` |
| 读 cookie + POST 到硬编码 IP | L4 | `infostealer + network` |
| 连矿池、占满 CPU | L4 | `miner` |
| 反向 shell / C2 | L4 | `backdoor + rat` |
| 混淆的 JS 从远端拉脚本执行 | L4(先标 LX 并动态验证) | `downloader + obfuscated` |
| 工具把用户填的地址当 webhook 发送 | L1 | `tool + network` |

## 报告里必须写清的

- 判定等级、依据的行为(带证据)、以及**哪些事没查/查不了**(没有源码、动态跑不起来、网络观察不到)。
- 不要用"应该没问题""大概率安全"这类话;不确定就写 LX 或写"未观察到,但 X 处无法确认"。
