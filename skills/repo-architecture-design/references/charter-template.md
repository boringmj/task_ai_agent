第 1 步的产出物。落成文件后交给用户确认;**确认之前不允许进入下一步**。

建议存放路径:`reports/<项目名>/charter.md`。

下面这份模板可以直接复制。方括号里是填写提示,写完后删掉。

````markdown

- **定稿日期**:<日期>
- **确认状态**:<待确认 / 已确认(注明由谁确认)>
- **目标仓库**:<路径>

## 一、背景

按访谈七组填写。没问到的项写「未获取」,并挪到第七节的显式假设里。

| 组 | 结论 |

| 项目性质与去向 | <内部工具 / 对外产品 / 教学示例 ……;是否商业分发> |
| 团队与维护者 | <人数、技能栈、是否有运维> |
| 生命周期与阶段 | <原型 / MVP / 已上线 / 维护中;预期存活时长> |
| 规模与增长预期 | <当前规模;增长预期> |

## 四、代码风格约定

- **命名**:<类 / 函数 / 常量 / 文件名>

## 七、显式假设

用户未回答、由 AI 推断的项。**逐条标注「推断」**,影响大的单独标出请用户确认。

| 假设 | 依据 | 影响面 | 状态 |
| --- | --- | --- | --- |
| <例:假定不要求向后兼容> | <推断:用户未提及外部使用者> | <中:影响接口是否可改> | 待确认 |
````

填写要求:

- 每条结论都要能追溯到访谈的回答,**不要写「用户大概想要」**。
- 「明确不做」一节宁多勿少 —— 写清楚不做什么,比写清楚做什么更能防止范围蔓延。
- 显式假设必须真的列出来。一个空白的假设表通常意味着你在偷偷替用户拍板。
