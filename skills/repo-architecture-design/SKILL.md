# 架构设计与重构

把"改成什么样"和"怎么改过去"当成一件事来做:先定目标形态,再定迁移路径,最后分步执行。
两者的共同输入是一份**用户确认过的纲领** —— 没有纲领就开始改代码,是本技能最常见的失败模式。

## 五条铁律

1. **先问背景,再谈方案。** 项目背景是所有技术选型的输入(见 `references/interview.md`)。背景没问清就出结构方案,等于替用户拍板。
2. **用户没确认的决策,不许替他做。** 选型、风格、规模这三件事只给建议与代价对比,最终由用户拍板;用户不回答的,转成纲领里显式标注的假设。
3. **重构的验收标准是「行为不变」。** 重构不是重写:对外行为、数据格式、接口契约都要保持;能先补测试就先补测试。
4. **任何新增抽象都要过守门。** 新增一层、一个接口、一个工厂,都要能回答"它换来了什么、代价是什么"。规则见 `references/over-engineering.md`。
5. **目标形态匹配 (背景, 规模) 二维档位。** 不是越工程化越好,也不是越小越好,而是匹配。500 行的教学脚本和 5 万行的内部平台,该长成两个样子。

## 流程

八步,其中**第 0 步是阻断点**:没完成背景访谈,不许出任何结构方案。

### 第 0 步:背景访谈(阻断)

按 `references/interview.md` 走,分两轮:

- **第一轮只问背景七组**(项目性质、团队、生命周期、规模增长、运行环境、硬约束、历史动因),其余给默认值。
- **第二轮按背景自适应追问**:能由背景推出的不再问,推不出的才追问(重构方向、技术选型三态、代码风格、规模预算)。

第一轮五到七问足够,别一上来甩三十个问题。每题给候选项,让用户选而不是写作文。

### 第 1 步:定稿《重构纲领》

用 `references/charter-template.md` 落成文件,写进工作区(建议 `reports/<项目名>/<项目名>-重构纲领.md`),让用户过一遍。纲领至少含:

- 背景摘要(七组的结论)
- 重构方向与**本次不做什么**
- 技术选型三态表(语言版本 / 框架 / 依赖 / 构建 / 测试 / 风格工具:保持、升级还是替换,各附理由)
- 代码风格约定(命名、文件粒度、目录扁平度、注释语言、类型注解、错误处理)
- 规模与预算(目标文件与类的数量级、允许的改动上限)
- 验收标准(「行为不变」具体怎么验)
- 显式假设(用户没答、由你推断的,逐条标注并注明「推断」)

> 用户确认之前,不要进入下一步 —— 跳过这里是整个流程里代价最高的失误。

### 第 2 步:现状评估

- 跑 `scripts/size_report.py <目标路径>` 拿到规模数字(文件数、行数、类与函数数、最大文件、目录深度)。
- 结构分析复用 `repo-structure-analysis` 的 `scripts/scan_repo.py`(容器路径见那个技能说明)。
- 需要安全视角时可借用 `repo-security-audit` 的扫描,但不要把重构报告写成安全报告。

### 第 3 步:设计目标结构

产出四样:目录树(每个文件标注职责与改动标记)、类与模块职责清单、依赖关系 mermaid 图、以及**明确的「不做什么」清单**。

改动标记统一用:`[新] [移] [改] [保] [删]`。

### 第 4 步:过度设计守门(不可跳过)

拿 `references/over-engineering.md` 逐条自查:抽象准入、类数上限、目录深度、配置项数量、是否需要那层"以后会用到的"预留。把结论写进报告。

**被砍掉的抽象要连同理由一起列出** —— 这比多给几层更有价值。

### 第 5 步:分步迁移路径

- 每一步都能独立验证、独立提交、独立回退。
- 优先「先加新的、再切过去、最后删旧的」,不要原地大改。
- 标明步骤之间的依赖,以及哪些步骤可以并行。
- 步骤超过五个时,交给 `task-orchestration` 落成计划文件再执行。

### 第 6 步:执行

按计划改,每步对照第 1 步定下的验收标准检查。发现纲领与现实冲突时**停下来找用户**,不要顺手改方向。

### 第 7 步:出报告

按 `references/report-template.md` 写,存到 `reports/<项目名>/`。

## 常见失败模式

- **背景没问就给一套「最佳实践」结构** —— 用户用不上,或者过度设计落不了地。
- **纲领没确认就动手改** —— 改到一半方向变了,全部返工。
- **把重构写成重写** —— 行为变了,原本是 bug 的地方被"顺手修好",引入回归。
- **只给目标结构、不给迁移路径** —— 用户看得懂,但不知道怎么走过去。
- **守门环节走过场** —— 每个抽象都"以后可能有用",最后落不了地。

## 附带资源

- `references/interview.md` —— 背景优先的访谈清单、背景到选型的映射表、自适应追问规则。
- `references/over-engineering.md` —— (背景 × 规模) 二维档位表与量化守门规则。
- `references/refactor-patterns.md` —— 常见重构手法目录:信号、做法、代价、何时不该用。
- `references/charter-template.md` —— 重构纲领模板。
- `references/report-template.md` —— 重构报告骨架。
- `scripts/size_report.py` —— 规模统计(文件 / 行 / 类 / 函数 / 最大文件 / 目录深度),输出 JSON 与摘要。

跑脚本时路径换算成容器里的 `/skills/repo-architecture-design/scripts/size_report.py`。
