# 架构迁移

迁移和重构的风险模型不同,别混着做:

- **重构**:形态基本不变,验收标准是「行为不变」,发现问题随时可以停。
- **迁移**:形态改变,验收标准是「行为在允许范围内变化」,必须预先设计回滚点。

所以本技能的重心不在"目标架构长什么样",而在 **该不该迁、怎么迁、迁砸了怎么办**。

## 五条铁律

1. **先做 Go/No-Go,再谈方案。** 相当一部分迁移诉求,正确答案是"不迁"。给出收益、成本、风险与替代方案的对比,让用户决定。
2. **验收靠对账与回滚,不靠"测试通过"。** 迁移会改变行为是常态,判定标准是新旧两套的**结果一致性**,以及出问题时能退回去。
3. **数据迁移是核心工作,不是收尾步骤。** 数据量、一致性、割接窗口往往决定整个方案的可行性。
4. **每一步都要有回滚点。** 不可逆操作(删旧库、改数据格式、下线旧服务)必须单独列出并请用户确认。
5. **并行运行优先于大爆炸切换**,除非用户给出明确理由(如旧系统根本无法与新系统共存)。

## 流程

九步。第 2 步是**否决点** —— Go/No-Go 结论为否时,直接停下,不进入方案设计。

### 第 0 步:界定范围

确认迁移的**两端**:从哪里(现状技术栈、部署形态、数据规模),到哪里(目标形态)。
范围要落到具体组件,不要停在"迁到云上"这种粒度。

### 第 1 步:背景

背景访谈复用 `repo-refactoring` 的清单(容器路径 `/skills/repo-refactoring/references/interview.md`),但关注点不同 —— 迁移要额外问清:

- 迁移的**动因**是什么(成本、性能、合规、供应商锁定、团队技能)?
- 有没有**硬期限**(合同、审计、旧系统下线日期)?
- 谁来执行、能不能短暂停机?
- 出问题时**能不能退回**旧系统(旧环境会保留多久)?

### 第 2 步:Go/No-Go 评估(否决点)

按 `references/feasibility.md` 走。产出一份对照:收益、成本、风险、替代方案(不迁或小改)。
结论就是三选一:**值得迁 / 有条件迁移 / 不建议迁**。给出建议后由用户拍板。

### 第 3 步:依赖面盘点

逐类列清单,标出可迁移性:

- 代码与构建产物
- 数据(库、文件、对象存储、缓存)
- 配置与密钥
- 外部集成(谁调用你、你调用谁、接口契约)
- 运维设施(监控、日志、备份、告警)
- 人员技能与文档

凡是有外部调用者的,先确认接口契约是否保持 —— 这决定能不能并行运行。

### 第 4 步:策略选择

按 `references/strategies.md` 四选一:大爆炸、绞杀者(逐步替换)、并行运行、双写。
给出推荐与理由;推荐通常不是大爆炸。

### 第 5 步:数据迁移方案

按 `references/data-migration.md` 设计:结构映射、全量与增量、一致性校验、割接窗口、失败处理。

### 第 6 步:回滚设计

按 `references/rollback.md` 走:每个阶段定义回滚点与回滚判据,标出不可逆操作。

### 第 7 步:分阶段计划

按阶段输出,每阶段含:目标、验收条件、回滚点、预计工期。阶段超过五个时交给 `task-orchestration` 落成计划文件。

### 第 8 步:出报告

按 `references/report-template.md` 写,存到 `reports/<项目名>/`。

## 与 repo-refactoring 的边界

| | repo-refactoring | architecture-migration |
| --- | --- | --- |
| 形态 | 基本不变 | 变(框架 / 语言 / 部署 / 存储) |
| 验收 | 行为不变,测试通过 | 行为允许变化,以对账与回滚兜底 |
| 风险 | 低,可随时停 | 高,必须预留回滚点 |
| 数据 | 不动 | 通常是核心难点 |
| 前置确认 | 背景 + 方向 + 选型 + 风格 + 规模 | 背景 + Go/No-Go + 策略选择 |

同时出现"迁移 + 重构"诉求时:**先迁后重构**。在迁移过程中顺手重构,会让对账失去基准 —— 分不清差异是迁移引入的还是重构引入的。

## 常见失败模式

- **跳过 Go/No-Go** —— 花几个月迁完,发现收益还不如优化现有系统。
- **大爆炸切换** —— 没有并行期,没有回滚点,一次失败全线停摆。
- **低估数据迁移** —— 代码搬完了,数据对不上,割接日才发现。
- **迁移中顺带重构** —— 新旧结果不一致时无法定位原因。
- **假设旧系统可以随时回退** —— 实际上旧库已改、旧服务已停,退不回去。

## 附带资源

- `references/strategies.md` —— 四种迁移策略的适用场景与代价。
- `references/data-migration.md` —— 数据迁移的结构映射、一致性校验与割接。
- `references/rollback.md` —— 回滚点设计与不可逆操作识别。
