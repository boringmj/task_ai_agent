# 迁移方案报告骨架

第 8 步的产出物。存到 `reports/<项目名>/<项目名>-迁移方案.md`。

````markdown
# <项目名> 迁移方案

- **日期**:<日期>
- **迁移两端**:<从 …… 到 ……>(两端都要落到具体技术栈与部署形态)
- **动因**:<一句话说清为什么要迁>
- **依据评估**:`reports/<项目名>/<项目名>-迁移评估.md`(如有)

## 一、背景与范围

- 迁移涉及哪些组件、哪些数据、哪些外部集成
- 明确**不包括**什么(范围边界)
- 硬期限与不可协商的约束

## 二、Go/No-Go 结论

| 维度 | 结论 |
| --- | --- |
| 可测收益 | |
| 成本估算 | |
| 主要风险 | |
| 替代方案 | |
| **综合结论** | 值得迁 / 有条件迁 / 不建议迁 |
| 前置条件 | |

若用户决定与评估结论不一致,在此如实记录并保留风险说明。

## 三、依赖面盘点

| 类别 | 内容 | 可迁移性 | 备注 |
| --- | --- | --- | --- |
| 代码与构建 | | | |
| 数据 | | | |
| 配置与密钥 | | | |
| 外部集成 | | | |
| 运维设施 | | | |
| 人员与文档 | | | |

## 四、策略选择

- **选用策略**:<大爆炸 / 绞杀者 / 并行运行 / 双写;组合的话写明哪阶段用哪种>
- **理由**:<为什么不是其它三种>
- **过渡期形态**:<新旧如何共存;共存多久>

## 五、数据迁移方案

- 数据盘点摘要(体量、分布、敏感度)
- 结构映射表
- 迁移方式(全量 / 增量 / 双写)与变更点记录方式
- 一致性校验口径与差异处理流程
- 割接窗口内的操作顺序,以及预演记录的实际耗时

## 六、回滚设计

| 阶段 | 回滚动作 | 预计耗时 | 前置条件 | 可逆性 |
| --- | --- | --- | --- | --- |

- **不可逆操作清单**及其执行时机
- **回滚判据**(指标、阈值、决策人、时限)
- 回滚演练记录

## 七、分阶段计划

每阶段含:目标、交付物、验收条件、回滚点、预计工期、依赖关系。

1. **<阶段名>** —— 目标 / 验收 / 回滚点 / 工期 / 依赖
2. ……

阶段超过五个时,一并产出 `task-orchestration` 格式的计划文件。

## 八、未确认与风险

- 依赖用户或第三方确认的项
- 评估中标注为「待验证」的假设
- 已知但未消除的风险,以及缓解措施

## 九、附录

- 扫描与评估的原始产物路径
- 相关脚本与命令
````

写作要求:

- 结论必须能对上依据,不要出现"预计不会有问题"这类无支撑的判断。
- 回滚那一节**不能省**,也不能只写"可以回滚" —— 要写清回滚动作、耗时与前置条件。
- 事实与推断分开写,推断一律标注。
