# 迁移策略

四种基本策略。选哪种决定了后续所有工作的形状,所以要在第 4 步明确写下来并请用户确认。

## 1. 大爆炸(Big Bang)

一次性切换到位,旧系统直接停用。

- **适用**:系统规模小;停机窗口可接受;新旧两套无法共存(如换了不兼容的框架)。
- **代价**:没有并行期,没有可比对的基准,**回滚只能靠提前备好的完整快照**。
- **风险**:四种里最高。一次失败就是全线停摆。
- **要求**:必须准备完整的回退预案,并明确回退的**决策时限**(多久内必须决定退不退)。

## 2. 绞杀者(Strangler Fig)

在入口处做路由,新系统逐个替换旧系统的功能模块,替换完一块就下线一块。

- **适用**:单体拆服务;旧系统不能停;可以按模块切分。
- **代价**:需要一个路由层;过渡期内两套系统并存,数据同步与部署复杂度上升。
- **风险**:中。主要是过渡期的双栈维护成本容易被低估。
- **要求**:明确模块的切分顺序(先切低风险、低耦合的),以及路由层的归属。

## 3. 并行运行(Parallel Run)

新旧两套同时处理同样的输入,对比输出结果。

- **适用**:结果可对账;正确性要求高(计费、结算、风控)。
- **代价**:成本翻倍;对账逻辑本身也要开发,且不能假设新系统一定对。
- **风险**:低 —— 发现不一致时旧系统仍在正常服务。
- **要求**:定义清楚对账口径(哪些字段、允许哪些差异、差异如何处理)。

## 4. 双写(Dual Write)

新旧存储同时写入,读路径逐步切换过去。

- **适用**:数据迁移阶段,尤其是不能停机的场景。
- **代价**:一致性风险 —— 一次写失败、两次写顺序颠倒,都可能造成数据分叉。
- **风险**:中高。必须有补偿与对账机制,不能只靠"大概率会成功"。
- **要求**:明确写入失败时的处理(重试、告警、还是回滚整笔)、以及定期的全量对账。

## 怎么选

| 条件 | 推荐策略 |
| --- | --- |
| 系统小、可停机、新旧不兼容 | 大爆炸(配完整回退预案) |
| 旧系统不能停、可按模块切 | 绞杀者 |
| 正确性要求高、结果可对账 | 并行运行 |
| 数据层迁移、要求不停机 | 双写 + 定期对账 |
| 完全无法判断 | 先取其中一个模块做绞杀者试点,拿到数据再定全局策略 |

**默认推荐不是大爆炸。** 只有当用户给出明确理由(如旧框架与新框架无法共存、或系统确实很小)时才用。

## 混合使用

实际项目常常组合:

- **绞杀者 + 双写**:功能逐个切走,数据在切换期双写。
- **并行运行只用于关键路径**:全量并跑太贵,通常只对结算这类高风险链路并跑。
- **先并行验证、再大爆炸切换**:用一段时间验证新系统正确后,再一次性切流量。

把这些组合写进方案的阶段划分里,并逐阶段标出用的是哪种策略。
