# 路径与命名约定

## 一律写相对路径

| 写什么 | 怎么写 | 谁把它变成真实位置 |
| --- | --- | --- |
| 自己的资源 | `scripts/foo.py`、`references/bar.md` | `load_skill` 的返回里会列出每个资源的实际位置 |
| 别的技能的资源 | `技能名/scripts/x.py`(并在 frontmatter 里声明 `skill: 对方`) | 同上,位置由依赖声明负责 |
| 工作区里的东西 | `clones/x`、`reports/x/` | 容器的工作目录就是工作区根,直接用 |

**绝对路径是明令禁止的**(`/skills/...`、`/workspace/...`),自检会拦。两个理由:

- **技能是要能搬的。** `/skills` 和 `/workspace` 都只是**当前这个宿主**的挂载点,换个环境
  这句话就是错的 —— 写死它就等于把技能和这个项目焊在一起。
- **它会悄悄过期。** 技能改名、资源挪位置,写死的路径不报错、不失效,只是**指向一个不存在的
  东西**,要等你真的去跑才发现。相对路径**根本不会过期** —— 位置从来就没被写下来过。

## 产出位置统一

| 什么 | 放哪 |
| --- | --- |
| 分析型技能的产出(报告、扫描 JSON) | `reports/<目标名>/` |
| 任务计划 | `plans/<任务名>/` |

以前是各挑各的(有的丢在工作区根叫 `findings-x.json`,有的叫 `quality-x.json`),散着。
统一之后有三个好处:找得到;**派活时 `write=["reports"]` 一个范围就够**(子 agent 的写权限
是按范围划的,散着放就会漏掉某一块,跑到最后一步才被挡下来);自检也查得动。

## 固定名字用英文

目录名、文件名是**标识符**:会被脚本引用、要在终端里敲、这项目还踩过 GBK 的坑。

**中文留给正文和报告内容。** 由内容派生的那部分(`<仓库名>`、`<任务名>`)跟着原名走,
不用翻译 —— 只有"骨架"要统一。

```text
reports/my-repo/audit.md          ✓ 骨架英文,仓库名照抄
reports/我的仓库/代码质量.md        ✗ 骨架用了中文
```
