# 编写技能

技能是**按需加载的说明书** —— 平时只占一行(名字 + 何时使用),需要时才把正文读进来。
所以它适合放"**只在特定场合才用得上的、成体系的**知识与流程",不适合放"任何时候都该遵守的纪律"
(那些属于系统提示词)。

## 目录结构

在项目根的 `skills/` 下建一个目录,目录名就是技能名:

```text
skills/<技能名>/
    SKILL.md          必需
    scripts/          可选:可执行脚本
    references/       可选:按需读进上下文的参考资料
    assets/           可选:产出里要用的文件(模板、图标)
```

`SKILL.md` 必须以一小段 frontmatter 开头,用 `---` 包起来:

```markdown
---
name: <技能名,和目录名一致>
description: <什么时候该用这个技能>
---

# 标题

正文……
```

## description 是关键,要写"什么时候用"

**清单里只显示 name 和 description** —— 模型就是靠这一行判断"现在该不该翻开它"。
所以要写**触发条件**,不是写"这个技能讲什么":

- ✅ 好:当用户要求审阅代码、或改完代码想检查有没有问题时使用。
- ❌ 差:关于代码审阅的说明。 —— 模型看完不知道什么时候该用

措辞上建议用第三人称陈述("……时使用"),而不是祈使句("请使用这个技能……")。

## markdown 格式有硬要求 —— 交出去之前先自查

**技能是给人看的 markdown 文件。格式不规范的话,用户一打开就是满屏 lint 警告,非常影响观感。**
所以写完**必须**用容器里的校验脚本过一遍,别凭感觉:

```bash
python /skills/writing-skills/scripts/check_skill.py /skills/<技能名>
```

它会同时查 frontmatter 和 markdown 结构。最容易踩的几条(编号是 markdownlint 官方规则号,方便对照):

- **MD022 标题上下都要空一行** —— 最常见的一条:`### 步骤` 下一行直接接内容就会报。标题下面必须空一行。
- **MD032 列表上下都要空一行** —— 列表前面是段落文字时,中间要空一行;列表后面同理。
- **MD031 代码块上下都要空一行** —— 围栏前后都得空行。
- **MD040 代码块要标语言** —— ` ``` ` 后面写 `text` / `python` / `bash` / `markdown`
  都行,但**不能不写**。
- **MD041 / MD025** —— 正文第一个非空行要是一级标题;且全文**只能有一个** `#`。
- **MD013 行太长** —— 上限 80 个字符,但**只对含空格、本来能换行的行报**;纯中文行没有空格,不受影响。要写长句时优先换行。
- **MD012 / MD009 / MD047** —— 不要连续空行、行尾不要多余空格、文件结尾留且只留一个换行。
- **MD004 无序列表符号统一** —— 全文统一用 `-`,别混用 `*` 和 `+`。

## 多层代码块嵌套(容易忽略的坑)

写技能时经常要**示范一段 markdown**,而那段示例本身又含代码块 —— 这时内层的围栏会把外层
**提前闭合**,后面整篇的结构就乱了。

办法是**外层用更长的围栏**:外层四个反引号,内层三个。像这样:

````markdown
这个技能要求按下面这个模板写报告:

```bash
python /skills/<技能名>/scripts/x.py
```

模板结束。
````

要点:

- 外层围栏**必须比内层长**(四个反引号包住三个反引号),不然内层会先把外层关掉。
- 外层也要标语言 —— 上例标的是 `markdown`,因为示范的是一段 markdown。
- 校验脚本按 CommonMark 的规矩判闭合(闭合围栏不短于开启的),所以嵌套写法它能认。

## 正文该写什么

写**具体怎么做**:步骤、判断依据、容易踩的坑、判断标准。可以引用工具名(比如
"先 `read_file` 看一眼")—— 技能和工具是配合关系,不是替代关系。

写的时候想清楚:模型**看到这篇正文之后**,行为会有什么不同?如果答案是"没什么不同",
那这篇就不值得存在。

## 附带资源

- `scripts/` —— **可以执行而不必读进上下文**。所以重的活(批量处理、格式转换)适合写成脚本,
  让模型只跑它、不读源码。
- `references/` —— 大段参考资料(规范、清单、示例集)。正文里点明"需要时去读哪个",
  而不是把内容整个抄进正文。
- `assets/` —— 产出里要被复制/引用的文件(模板、字体、图片)。

**这些文件是怎么被用到的**:技能目录在工作区**之外**,文件工具够不到它;但它被**只读**
挂载进容器,所以要用 `run_command` / `run_python` 走容器那条路:

```text
skills/<技能名>/scripts/foo.py   →   容器里:/skills/<技能名>/scripts/foo.py
```

正文里写"跑 `scripts/foo.py`"时,模型会自动换算成上面那个容器路径(`load_skill` 也会
把每个资源的实际路径列出来)。只读:能跑能读、改不了;VM 里看不到。

## 加完之后

技能是**自动发现**的:目录建好、`SKILL.md` 写好,下次启动就会出现在技能清单里,
不需要改任何代码或提示词。可以用 `load_skill("<技能名>")` 验证能不能读出来。
