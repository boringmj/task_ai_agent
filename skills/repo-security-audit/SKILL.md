# 仓库安全审计

输入是一个仓库(通常克隆在 `clones/` 下),产出是一份**中文安全审计报告**:候选漏洞清单(带证据与置信度)、人工确认后的问题、以及把多个问题串起来的**利用链分析**。

两个扫描脚本 + 五份参考资料,配合起来做:先机器快扫(广度),再人工确认(准度),最后串链(深度)。

## 五条铁律

1. **先确认授权。** 只审计用户自己的代码,或用户明确被授权评估的目标。开跑前用一句话跟用户确认范围;拿不准就问,不要默认可以。
2. **命中 ≠ 漏洞。** 脚本给的是"这里有个危险点"的**候选**。构成真漏洞要同时满足:①参数可控 ②数据能到达该点 ③中间没有拦截。②③只能靠读代码判断,这是你(模型)的核心工作。
3. **重活给脚本,别通读仓库。** 先跑出全局清单,再按需读少量关键文件。把整个仓库读进上下文既慢又容易撑爆。
4. **利用链只到"思路 + 前置条件"级。** 交付物是分析报告,不是武器:不产出可直接复制运行的 exploit 组合,不在未授权目标上验证。
5. **当前代码干净 ≠ 仓库干净。** 密钥可能不是"没写过",而是"删过" —— 被删的内容仍在 `.git` 里,见第 3 步。

## 步骤

### 1. 界定范围

- 确认目标仓库在 `clones/<名字>`,先 `list_files` 看根目录、读 `README*` 弄清它是干什么的。
- 问清(或从上下文判断):这个仓库是自研的还是第三方的?审计目的是上线前检查、还是应急排查?
- 记下技术栈:语言、框架、部署方式。这决定后面重点看哪些规则类别。

### 2. 跑快扫脚本

脚本在容器里跑,**路径要换算**成 `/workspace/...` 或 `/skills/...`(宿主路径 `D:\...` 在容器里不存在)。

```bash
# 依赖 pyyaml(已装在 .pylibs 就不用重复装);bandit 缺失会自动跳过
python /skills/repo-security-audit/scripts/scan.py \
    /workspace/clones/<仓库> --out /workspace/findings-<仓库>.json
```

子命令(默认全跑,也可以只跑其中几项):

| 子命令 | 作用 |
| --- | --- |
| `secrets` | 硬编码凭据、私钥、高熵串、`.env` 明文赋值 |
| `patterns` | 危险 API 与漏洞模式(Python / JS-TS / Java / Go / PHP + 通用 Web) |
| `config` | Docker / Compose / K8s / CI / nginx / 框架与工程配置 |
| `deps` | 依赖清单 → OSV 漏洞库(需联网,`--offline` 可跳过) |
| `bandit` | 调用 bandit 做 Python 深度扫描(已装则自动带上) |
| `all` | 以上全部(默认) |

常用选项:`--exclude 'glob'` 追加排除、`--max-size` 调单文件上限、`--top N` 调摘要条数。

脚本会打印摘要并把完整清单写进 JSON。**先只看摘要**,别把 JSON 整个读进上下文 —— 需要细节时用 `read_file` 按行取。

### 3. 扫 git 历史(别跳过)

当前分支看不到的问题,可能只是被"删掉"了 —— 内容仍在 `.git` 对象库里,攻击者拿到仓库就能翻出来。被删的 `.env`、旧版硬编码口令、force-push 丢弃的提交,都在这里现形。

```bash
python /skills/repo-security-audit/scripts/scan_git.py \
    /workspace/clones/<仓库> --out /workspace/git-findings-<仓库>.json
```

脚本遍历所有提交与分支(加 `--dangling` 还能覆盖 rebase / force-push 遗留的不可达对象),把**历史版本的密钥**和**已删除的敏感文件**挖出来,并标注当前分支是否还有这份内容。

- `git_status: deleted` 的最要紧 —— **文件删了,秘密没删**。脚本会自动给这类提一档严重度。
- 结论要和静态扫描**合并去重**:同一个问题当前代码里也有的话,以静态扫描那条为准。
- 浅克隆(`--depth=1`)没有历史,遇到时提醒用户重新完整克隆再扫。

定级与处置(轮换优先于清理)见 `references/git-history.md`。

### 4. 逐条分诊(最关键的一步)

对摘要里的每条候选,判断是**真问题**还是假阳性。先按严重度**倒序**处理,高危的先看。

- 用 `read_file(path, start_line=..., end_line=...)` 读命中行的**上下文**(前后 20~40 行足够),不要整文件读。
- 问三个问题:**参数从哪来?**(用户可控 / 配置常量 / 内部生成)**中间有没有过滤?**(校验、转义、白名单、权限装饰器)**这段代码真的会被执行吗?**(死代码、测试、示例目录都排除)
- 明确的假阳性来源:测试与 fixture、示例配置、文档、mock、已废弃分支、把常量当输入。
- **用 `grep_files` 追数据流**:把变量名当关键词搜,看它在哪里被赋值、在哪里被传进来。这是从 sink 反推 source 的主要手段。
- 每条给出结论:确认 / 很可能 / 存疑,并写清依据(文件:行)。

分诊门道和各类模式的确认要点见 `references/vuln-patterns.md`。

### 5. 判定严重度与置信度

按 `references/severity-rubric.md` 打两个维度:

- **严重度**:critical / high / medium / low / info —— 看影响面(能否 RCE、能否拿全量数据、是否越权)+ 前置条件(远程还是本地、是否需要登录)。
- **置信度**:确认 / 很可能 / 待验证 / 存疑 —— 看证据强度,别把"看起来像"写成"确认存在"。

两者都要写,不要只留一个。一份"高危但存疑"和一份"中危但确认",对用户的意义完全不同。

### 6. 串利用链

**这一步才是审计的价值所在,不要跳过。** 单点的低危问题,组合起来往往直通高危。

方法(详见 `references/exploit-chain.md`):

1. 列出**敏感终点**:管理后台、数据库、云凭据、对象存储、支付流程、用户 PII。
2. 列出你已确认的**原语**:每个问题能产出什么(一段文件内容、一次命令执行、一个 token、一次任意查询)。
3. 用原语的产出,去够下一个入口的**前置条件** —— 能接上就是一条链。
4. 逐跳标注**闸门**:哪一步需要登录?哪个边界(NAT / WAF / 权限)挡着?把不确定的也写出来。

### 7. 出报告

按 `references/report-template.md` 的结构写,存到工作区,文件名 `<仓库名>-security-audit.md`。要求:

- 每条问题都带**证据**(`文件:行`)和**修复建议**;结论要与证据对得上。
- 利用链单列一节,写清每跳的依据和未验证的假设。
- 结尾写「未覆盖范围」:没扫的语言、联网失败跳过的依赖、看不清的地方。

## 常见坑

- **路径换算。** 文件工具返回宿主路径,脚本要的是 `/workspace/...`;照抄会 `FileNotFoundError`。
- **同一行被多条规则命中**属正常(通用规则 + 语言规则 + bandit 交叉覆盖),报告里合并成一条,不要当成多个问题。
- **正则只认文本。** 动态导入、反射、字符串拼接出来的调用、跨文件的类型流,脚本都抓不到 —— 这些正是你读代码时要补的。
- **别只信摘要。** 摘要按严重度取样,低危里也可能藏着串链要用的关键点(比如一个能读配置的路径穿越)。串链阶段可以回头翻 JSON。
- **别把第三方库的坑当成本项目的坑。** `node_modules` / `vendor` 里的代码已被排除;依赖风险走 `deps` 那一路。

## 附带资源

- `scripts/scan.py` —— 工作区静态快扫器,数据驱动,规则在 `scripts/rules/*.yaml`。
- `scripts/scan_git.py` —— git 历史扫描器(纯 dulwich,不需要 git 命令)。
- `scripts/rules/` —— `secrets.yaml`(密钥)、`sinks.yaml`(危险 API)、`config.yaml`(配置)。**要扩规则直接改这里,不用动代码**;字段说明见各文件头部注释。
- `references/vuln-patterns.md` —— 各类漏洞的 source→sink、语言差异、确认要点、常见误报。
- `references/exploit-chain.md` —— 利用链的构成要素与常见链模板。
- `references/severity-rubric.md` —— 严重度与置信度的判定标准。
- `references/report-template.md` —— 报告骨架。
- `references/git-history.md` —— 历史泄露的判断与处置(轮换、filter-repo)。
